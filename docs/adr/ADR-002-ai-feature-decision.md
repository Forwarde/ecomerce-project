# ADR-002: Внедрение ИИ-парсера текстовых заявок клиентов в AtelierFlow

* **Статус:** Принято (Accepted)
* **Дата:** 2026-11-27
* **Авторы:** `@Forwarde` (PM), `@Forwardzhemae` (PO/BA)
* **Связь с артефактами:** [`docs/lab12-ai-feature-evals-cost.md`](../lab12-ai-feature-evals-cost.md), [`docs/lab12-eval-dataset.csv`](../lab12-eval-dataset.csv)

## Контекст и постановка проблемы
Администраторы швейного ателье тратят в среднем 6 минут на ручной перенос параметров пошива и индивидуальных мерок из свободных текстовых сообщений клиентов (WhatsApp/Telegram) в форму заказа AtelierFlow. Базовое правило на регулярных выражениях (Regex) на 30 реальных примерах показало точность лишь **43.3%**.

## Рассмотренные варианты

1. **Вариант 1 — Отказаться от ИИ (оставить только ручной ввод + Regex)**
   - *Плюсы:* Нулевая стоимость API, полная детерминированность.
   - *Минусы:* Сохраняются потери времени администратора (~13.5 ч/мес.) и высокая вероятность ручных опечаток при переносе цифр.
2. **Вариант 2 — Развернуть собственный GPU-сервер для self-hosted LLM (`Qwen 2.5 7B` через Ollama/vLLM)**
   - *Плюсы:* Данные не покидают контур сервера в РК, нет зависимости от внешнего API.
   - *Минусы:* Аренда GPU-сервера 24/7 стоит ~124 000 ₸/мес. (\$248/мес.), что в 1 900 раз дороже API при текущем объеме 600 заявок/мес. (окупается только от 1.18 млн запросов/мес.).
3. **Вариант 3 — ИИ-парсер через легкий LLM API (Gemini 2.5 Flash / GPT-4o-mini) с очисткой ПДн и Human-in-the-Loop (ВЫБРАНО)**
   - *Плюсы:* Точность **90.0%** (27/30 на eval-наборе), `0` галлюцинаций чисел, стоимость **\$0 на Free Tier** (или \$0.13/мес. на Paid Tier), мгновенный fallback на ручную форму при сбое API.
   - *Минусы:* Требует обязательного модуля маскировки ФИО/телефона до отправки запроса и ручного подтверждения черновика оператором.

## Решение
Принято решение **реализовать Вариант 3**: внедрить ИИ-парсер заявок в фазе Release 3.1 с:
1. Предварительным вырезанием ПДн (телефон, ФИО) на сервере до вызова LLM API;
2. Обязательным **Human-in-the-Loop** (ИИ заполняет только черновик формы, сохраняет заказ человек);
3. Хранением «золотого» eval-набора (`docs/lab12-eval-dataset.csv`) для регрессионной проверки при смене промпта или модели.

## Последствия
* **Положительные:** Сокращение времени обработки заявки в 4 раза при околонулевом OPEX (< 700 ₸/мес. даже при 10-кратном росте).
* **Отрицательные / Ограничения:** Заказы из нескольких изделий в одном сообщении (пример #26) потребуют обновления JSON-схемы до массива `items[]` во второй итерации.
