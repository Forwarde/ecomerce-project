# ADR-003: Выбор бесплатного Open Source стека для хостинга, CI/CD, DORA и нагрузочного тестирования

* **Статус:** Принято (Accepted)
* **Дата:** 2026-11-26
* **Авторы:** `@Forwarde` (PM / DevOps)
* **Связь с артефактами:** [`docs/lab08-sow-sla-budget-finops.md`](../lab08-sow-sla-budget-finops.md), [`docs/lab10-dora-release-plan.md`](../lab10-dora-release-plan.md)

## Контекст и постановка проблемы
Необходимо обеспечить непрерывную интеграцию (CI), контроль безопасности зависимостей, сбор метрик DORA, нагрузочное тестирование НФТ и надежный хостинг веб-приложения **AtelierFlow** при жестком бюджетном ограничении: **0 ₸ на лицензии коммерческого ПО** и предсказуемый минимальный OPEX на инфраструктуру.

## Рассмотренные варианты

1. **Вариант 1 — Коммерческие SaaS-сервисы и Managed Cloud (AWS ECS + RDS + Datadog + Jira Cloud Paid)**
   - *Плюсы:* Богатые коробочные дашборды и автоматическое масштабирование.
   - *Минусы:* Стоимость хостинга за 3 года превышает **2 070 000 ₸**, жесткий вендор-локин, риск неконтролируемых расходов (FinOps), привязка к банковской карте.
2. **Вариант 2 — Полностью локальный On-Premise сервер в помещении ателье**
   - *Плюсы:* Нет ежемесячной арендной платы за облако.
   - *Минусы:* Высокий стартовый CAPEX (650 000 ₸), риск простоя при отключении электропитания/интернета, нарушение SLA 99.5%.
3. **Вариант 3 — 100% Open Source стек (GitHub Actions + Trivy + Grafana k6 + Docker Compose на VPS + Uptime Kuma) — ВЫБРАНО**
   - *Плюсы:* **0 ₸ на лицензии**, бесплатные неограниченные минуты GitHub Actions для публичного репозитория, 3-летняя стоимость аренды VPS в РК составляет всего **360 000 ₸** (в 5.7 раза дешевле Managed Cloud), полная переносимость через Docker.
   - *Минусы:* Требует базовой настройки пайплайнов `.github/workflows/*.yml` и собственного скрипта расчета DORA.

## Решение
Принято решение **стандартизировать Вариант 3**:
* **CI/CD и безопасность:** `.github/workflows/ci.yml` + `aquasecurity/trivy-action`.
* **Метрики DORA:** `.github/workflows/dora.yml` + `scripts/dora_dashboard.py`.
* **Нагрузочное тестирование НФТ:** `k6/load-test.js` + `.github/workflows/k6.yml` (пороги `p95 < 1000 мс`, `errors < 5%`).
* **Хостинг и мониторинг:** Docker Compose на VPS в РК + `Uptime Kuma` для контроля SLA 99.5%.

## Последствия
* **Положительные:** Максимальный ROI проекта (**500%** за 3 года), нулевой вендор-локин и полная воспроизводимость стенда на любом компьютере.
* **Отрицательные:** Резервное копирование БД и обновления ОС VPS выполняются по регламенту Runbook силами поддержки (учтено 5 ч/мес. в бюджете OPEX).
