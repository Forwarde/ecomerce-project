# ЛЗ 12. План ИИ-функции для AtelierFlow: Evals, расчет стоимости инференса и карточка рисков

## 1. Описание ИИ-функции и постановка задачи

### Выбранная функция
**ИИ-парсер заявок клиентов из мессенджеров (WhatsApp / Telegram) в структурированную карточку заказа AtelierFlow.**
Клиенты ателье часто пишут в свободной форме (например: *«Здравствуйте, хочу сшить классический костюм-двойку из синей шерсти к 15 декабря, рост 178, грудь 102, талия 88»*). Администратор вручную переносит эти параметры в 7 полей формы заказа.

* **Бизнес-метрика:** Сокращение среднего времени занесения текстовой заявки в систему с **6.0 минут до ≤ 1.5 минут** (экономия ~13.5 часов администратора в месяц при 180 заказах).
* **Метрика качества модели (Model Metric):**
  - `Field-level F1 / Accuracy ≥ 90%` по 5 обязательным полям (`garment_type`, `fabric`, `deadline`, `measurements`, `urgency`);
  - `Critical Hallucination Rate = 0%` (модель не имеет права выдумывать отсутствующие в тексте числовые мерки — при отсутствии поля обязана возвращать `null`).
* **Базовое решение без ИИ (Baseline):** Жесткая веб-форма + поиск ключевых слов по регулярным выражениям (Regex). *Замер базового Regex-решения на нашем наборе из 30 сообщений дал точность всего **43.3% (13/30)**, так как клиенты пишут с опечатками, сокращениями («ОГ 96», «до пятницы») и смешивают русский/казахский языки.*
* **Критерий приемки (Acceptance Criteria):**
  1. На «золотом» eval-наборе из 30 реальных примеров точность полного извлечения полей ≥ **85%** (минимум 26 из 30 без ошибок).
  2. Ни в одном из 30 примеров модель не додумывает несуществующие мерки (`0` галлюцинаций цифр).
  3. Средняя задержка ответа API ≤ **2.5 секунды**.

## 2. Eval-набор (30 примеров) и результаты замера качества

Полный «золотой» датасет из 30 самостоятельно составленных примеров с эталонными ответами и фактическими результатами замера находится в файле:
👉 [`docs/lab12-eval-dataset.csv`](./lab12-eval-dataset.csv)

### Методика и результаты прогона (бесплатный стек)
* **Подход:** Structured Prompt Engineering (Few-shot JSON extraction, `temperature = 0.0`) — без дорогого fine-tuning и RAG, так как прайс и поля схемы компактно помещаются в системный промпт (~450 токенов).
* **Протестированные бесплатные модели:**
  1. **Baseline (Regex без ИИ):** `13 / 30` полностью верных (**43.3%**).
  2. **Локальная открытая модель `Qwen 2.5 7B Instruct` (Ollama, локально на 16 GB ОЗУ):** `25 / 30` полностью верных (**83.3%**), средняя задержка `3.8 сек`.
  3. **Бесплатный тариф API `Gemini 2.5 Flash` (Google AI Studio Free Tier):** **`27 / 30` полностью верных (90.0%)**, `0` галлюцинаций чисел, средняя задержка `0.9 сек`.

### Разбор 3 ошибок модели на eval-наборе (`Gemini 2.5 Flash`)
1. **Пример #09:** Клиент написал «к следующему вторнику» без даты → модель не смогла вычислить дату без передачи `current_date` в системный промпт *(исправлено добавлением текущей даты в промпт)*.
2. **Пример #18:** Смешанный запрос на казахском и русском («қара барқыттан камзол, белі 74») → модель перевела название ткани не в стандартный артикул справочника *(исправлено добавлением словаря из 12 тканей в промпт)*.
3. **Пример #26:** В одном сообщении сразу 2 разных изделия (пиджак + брюки) → плоская JSON-схема ожидала 1 объект *(ограничение схемы v1: массив `items[]` запланирован в v2)*.

## 3. Расчет стоимости инференса и сравнение с Self-Hosted GPU

### 3.1. Исходные параметры токенизации (`tiktoken` / `cl100k_base`)
* **Системный промпт + 2 few-shot примера + JSON-схема:** `450` input-токенов.
* **Среднее сообщение клиента ателье (40–60 слов на кириллице):** `150` input-токенов.
* **Итого Input на 1 запрос:** `600` токенов.
* **Средний JSON-ответ модели:** `200` output-токенов.

### 3.2. Официальные публичные тарифы (на дату расчета — ноябрь 2026)
* **Google Gemini 2.5 Flash API** ([ai.google.dev/gemini-api/docs/pricing](https://ai.google.dev/gemini-api/docs/pricing)):
  - Free Tier: бесплатно в пределах лимита запросов (RPM/RPD);
  - Paid Tier: **\$0.15 / 1M input-токенов**, **\$0.60 / 1M output-токенов**.
* **OpenAI GPT-4o-mini API** ([openai.com/api/pricing](https://openai.com/api/pricing)):
  - **\$0.15 / 1M input-токенов**, **\$0.60 / 1M output-токенов**.
* **Аренда GPU-сервера для self-hosted `Qwen 2.5 7B` (Ollama / vLLM)** ([vast.ai](https://vast.ai) / [runpod.io](https://www.runpod.io/pricing)):
  - 1× NVIDIA L4 / RTX 4090 (24 GB VRAM) 24/7 = **~\$0.34/час × 730 ч = \$248 / мес.** (~**124 000 ₸ / мес.** по курсу 500 ₸/\$).

## 4. Карточка рисков ИИ-функции (AI Governance & NIST AI RMF)

| Параметр карточки | Значение для AtelierFlow |
| :--- | :--- |
| **Категория риска (EU AI Act)** | **Limited / Minimal Risk** (вспомогательный инструмент автозаполнения формы, не принимает юридически значимых решений). |
| **Что происходит при ошибке модели?** | В форме создания заказа подставится неверный тип ткани или пропущенная мерка. При отсутствии контроля это приведет к ошибке раскроя ткани (убыток 15–40 тыс. ₸). |
| **Где человек в контуре (Human-in-the-Loop)?** | **Обязательная проверка на 100% заказов:** ИИ лишь заполняет черновик формы в `/admin`, подсвечивая извлеченные поля желтым фоном. Сохранение заказа в БД невозможно без ручного подтверждения администратором/закройщиком. |
| **Прозрачность (как пользователь узнает про ИИ)?** | В интерфейсе отображается бейдж **«✨ Черновик заполнен ИИ — проверьте мерки перед сохранением»**. |
| **Какие данные передаются провайдеру?** | **Строгая маскировка ПДн (PII Redaction):** перед отправкой в API регулярное выражение удаляет номера телефонов (`+7...`) и ФИО клиента; передается только безличный текст параметров пошива. |
| **Отказоустойчивость (Fallback)** | При недоступности внешнего API (> 3 сек) или исчерпании бесплатного лимита интерфейс мгновенно переключается на обычную ручную форму без блокировки работы ателье. |

## 5. Итоговое решение (ADR-002)
Принято решение: **ДЕЛАЕМ** в рамках Release 3.1 (после стабилизации базового MVP) на базе API с обязательной очисткой ПДн и Human-in-the-Loop, **без покупки/аренды собственного GPU-сервера**.
Оформлено в соответствии со стандартом MADR: [`docs/adr/ADR-002-ai-feature-decision.md`](./adr/ADR-002-ai-feature-decision.md).
